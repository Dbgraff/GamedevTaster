# Попробуй профессию: программист в геймдеве

Мини-профориентационная проба на 15–20 минут: две задачи (настройка физики
прыжка цифрами + выбор правильной строчки кода), пара вопросов-рефлексии и
короткий эвристический фидбэк в конце. Собрано на Vite + TypeScript,
без фреймворков — деплоится как статика на GitHub Pages.

## Запуск локально

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`.

## Деплой на GitHub Pages

1. Залей проект в свой репозиторий на GitHub (например, `gamedev-taster`).
2. В `vite.config.ts` поле `base` должно совпадать с именем репозитория:
   `base: "/gamedev-taster/"`. Если имя другое — поправь тут.
3. В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
4. Запушь в ветку `main` — workflow из `.github/workflows/deploy.yml`
   соберёт проект и задеплоит автоматически. Ссылка появится в разделе
   Pages настроек репозитория (обычно `https://<username>.github.io/<repo>/`).

## Важно: про ИИ-проверку

Сейчас фидбэк в конце (`src/feedback.ts`) — это эвристика по правилам
(если/иначе), а не настоящий вызов ИИ. Это специально: GitHub Pages отдаёт
только статику, и любой API-ключ, зашитый в клиентский JS, будет виден
любому в DevTools браузера.

Когда захочешь подключить настоящий ИИ-фидбэк:

1. Разверни маленькую serverless-функцию (Cloudflare Workers / Netlify
   Functions / Vercel — у всех есть бесплатный тариф с запасом для пилота).
   Она хранит API-ключ на сервере и на вход принимает `SessionState`
   (см. `src/feedback.ts`), а на выход отдаёт текст фидбэка.
2. Замени тело `getFeedback()` в `src/feedback.ts` на `fetch` к этой
   функции — сигнатура (`SessionState → Promise<string>` или строка)
   уже совместима, менять вызывающий код в `main.ts` почти не придётся.

## Структура

```
src/
  main.ts      — экраны и переходы между ними (интро → задача 1 → задача 2 → рефлексия → фидбэк)
  game.ts      — канвас-симуляция прыжка (физика, отрисовка)
  feedback.ts  — генератор фидбэка (сейчас — эвристика, см. выше про замену на ИИ)
  style.css    — тёмная тема
```

## Что можно добавить дальше

- Ещё модули-пробы для других профессий (геймдизайн, арт, нарратив) —
  по образцу текущего экрана: свой канвас/интерфейс + своя логика фидбэка.
- Сохранение результатов (сейчас всё живёт в памяти вкладки и пропадает
  при обновлении страницы) — для пилота с группой имеет смысл писать
  результаты куда-то (хоть в Google Sheets через простой webhook).
- Аналитика: сколько человек дошли до конца, на каком шаге отваливались.
